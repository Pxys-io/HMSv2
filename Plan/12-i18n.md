# Phase 12 — Internationalization (AR/EN) & RTL

**Revision 2.0:** translation QA now includes privacy-safe notification/email
copy, conflict/error states, and the revised operational/clinical status
vocabulary.

**Goal:** both apps fully bilingual (Arabic default), correct RTL everywhere,
proper fonts/numerals/dates, and a translation workflow that doesn't decay.

**Depends on:** 09, 11 (screens exist). **Blocks:** 13 (launch needs AR complete).

---

## 1. Deliverables

- i18next resource structure for both apps (namespaced)
- Complete AR translation pass (Egyptian-friendly MSA; reception templates colloquial where natural)
- RTL audit + fixes across every screen
- Localized dates/times/numbers
- Print + email templates verified in both locales
- Translation QA checklist

## 2. Rules

**I1 — Namespaces:** `common` (buttons, statuses, errors), `nav`, per-feature
(`board`, `exam`, `cashier`, `chat`, `booking`, `account`, `admin`…). Keys
`feature.element.purpose` (`exam.actions.complete`). English is the source of
truth; Arabic resource must reach 100% coverage before launch.

**I2 — No hardcoded strings.** eslint rule `no-literal-string`-style check via
a custom lint pass in CI (grep for `>[A-Za-z\u0600-\u06FF]{3,}<` in tsx) —
pragmatic, not perfect.

**I3 — Locale resolution:** user preference (account/staff setting) → a
non-sensitive locale cookie/localStorage value → default `ar`. Staff app switch
in topbar; public in header. Never persist auth, patient, appointment, chat, or
clinical data in localStorage.
Switching is instant (no reload): set `<html lang dir>`, swap font family class.

**I4 — RTL:** logical properties only (Plan/00 §9). Known traps to audit:
calendar grids, timeline rails, tables (first column becomes right), breadcrumb
chevrons, `DirIcon` mirroring, chat bubbles (own vs other sides), print `dir`.

**I5 — Numerals & units:** Western digits everywhere (Plan/00 §3). Money
`1,250.00 ج.م / EGP 1,250.00` via `Intl.NumberFormat(locale + "-u-nu-latn")`.
Dates `dayjs` locale `ar`/`en`, format `DD MMM YYYY` localized; times 12h
localized (`ص/م` vs `AM/PM`). Relative times ("5 min ago") via dayjs plugin.

**I6 — Pluralization:** Arabic has 6 plural forms — always use i18next
`count` plurals for counted strings (appointments, minutes, patients). Never
string-concatenate counts.

**I7 — Clinical terms stay Latin-script-friendly:** medication names print as
entered (drug DB has both name fields); ICD codes always LTR islands.

**I8 — Privacy-safe messages:** notification, email, TV, and public-account
translations may mention operational booking details only. They must not
translate or expose diagnoses, prescriptions, labs, imaging, or invoice details
outside their authorized staff screens.

## 3. Step-by-step tasks

1. Namespace files created for both apps (EN complete from built UI, AR translated).
2. `<html lang/dir>` management + font swap + `DirIcon` audit.
3. RTL walkthrough of every screen with the checklist (§4) — fix issues.
4. Date/number formatting helpers (`lib/format.ts`) applied everywhere (replace ad-hoc formatting).
5. Print templates AR/EN proofed with real data (all 5 doc types).
6. Email templates AR/EN proofed.
7. Coverage script: compare AR vs EN keys per namespace → must diff 0; run in CI.

## 4. RTL/translation QA checklist (per screen)

- [ ] Layout mirrored; no clipped text (Arabic is ~20% wider)
- [ ] Icons: directional flipped, non-directional not flipped
- [ ] Phone/code/money LTR islands (`<bdi>`)
- [ ] Plural forms correct for 0/1/2/few/many
- [ ] Mixed-script strings (Arabic + Latin name) order correctly
- [ ] Form validation messages localized
- [ ] Record-conflict, audit-unresolved, upload-quarantine, and offline states localized
- [ ] Tables: columns mirrored, sort icons correct side
- [ ] Print preview both locales on A4 + A5

## 7. Gotchas

- i18next `ar` plural categories: use `v4` plural format; test count=0,1,2,3,11.
- `Intl.NumberFormat("ar")` defaults to Arabic-Indic digits — always force `latn`.
- dayjs Arabic month names vary (miladi vs hijri spellings) — import `dayjs/locale/ar` and use `MMMM` consistently.
- Don't translate `booking_ref`, invoice numbers, or drug strengths.
